# Завершение сессии

Подготовь проверяемый handoff в репозитории для нового агента, который не видел этот разговор. История диалога служит свидетельством; фактическое состояние репозитория является источником истины.

## Порядок работы

На границе завершённого этапа используй **короткий перенос** ниже. Полный порядок нужен при явном запросе полного завершения, существенных незавершённых операциях или необходимости подробного восстановления. Не читай дополнительные references ради короткого переноса.

### Короткий перенос между этапами

1. Проверь только состояние, нужное следующему этапу: существование результатов, релевантные изменения Git и незавершённые действия. Уже полученные результаты тестов используй с указанием проверенного состояния; повторяй тесты, если относящиеся к ним файлы изменились или осталось сомнение.
2. Обнови `docs/SESSION_STATE.md`: цель следующего этапа, готовые результаты и пути, существенные ограничения, незавершённые действия и один `NEXT STEP`. `DECISIONS.md` и `TODO.md` обновляй только при новых решениях/задачах. Не создавай пустые файлы ради комплекта.
3. Верни краткий список изменённых файлов и один готовый промпт для новой сессии. Снимок и промпт вместе — обычно до 500 слов, максимум 1000 без явного запроса подробностей. Укажи неизвестные проверки и незавершённые операции; не сокращай их ради размера.
4. Новый агент читает только снимок, применимые `AGENTS.md` и нужные результаты. Не переноси в промпт историю разработки. Заверши `SESSION READY FOR HANDOFF` и инструкцией открыть новый чат вручную. Сам факт выдачи промпта не создаёт чат.

### Полное завершение

1. Не расширяй scope. Закончи только текущую безопасную атомарную операцию. Запущенную или неясную операцию зафиксируй; не повторяй, не отменяй и не перезапускай её ради чистого отчёта.
2. Найди корень репозитория и прочитай `AGENTS.md`, `docs/SESSION_STATE.md`, `docs/DECISIONS.md`, `docs/TODO.md`. Если state-файла нет, создай его из одноимённого шаблона в `assets/` этого навыка.
3. Проверь реальность: ветку и HEAD, `git status --short`, staged/unstaged diff, untracked-файлы, видимые хосту фоновые процессы и последние релевантные тесты/сборки. Результат проверки относится только к тому состоянию кода, на котором она выполнена. Недоступный факт пометь как неизвестный.
4. Перепиши `SESSION_STATE.md` как краткий актуальный снимок: цель, проверенное состояние репозитория, выполненное, изменённые файлы, evidence проверок, неудачи и действия, которые не надо повторять, незавершённые операции, блокеры и один конкретный `NEXT STEP`.
5. В `DECISIONS.md` добавь только существенные новые решения. Обнови `TODO.md`, не дублируя выполненные и активные пункты. Удали из handoff устаревшие предположения; не пересказывай хронологию чата.
6. Сверь все три state-файла с репозиторием глазами агента без доступа к чату. Противоречия разрешай в пользу проверенного состояния файлов/Git; нерешённые расхождения сохрани явно.
7. Не выполняй commit, push, discard, остановку процессов или другие внешние изменения без уже полученного разрешения. Незакоммиченная работа является допустимым состоянием handoff; staged, unstaged и untracked изменения опиши отдельно.
8. Сформируй результат по контракту ниже. Для выбора между `/compact` и чистой сессией прочитай [context-policy.md](references/context-policy.md).

## Контракт результата

Верни по порядку:

1. Краткий список обновлённых файлов.
2. Статус Git и проверок, включая неизвестные факты.
3. Один fenced-блок `text` с готовым промптом для нового чата. Включи корень репозитория, ветку и HEAD, восстановленную цель, проверенное состояние, предупреждения/неудачные подходы и точный следующий шаг. Промпт должен требовать прочитать четыре проектных файла, сверить их с Git/файлами, сообщить `Recovered / Current state / Next`, затем продолжить при отсутствии блокера.
4. `SESSION READY FOR HANDOFF`.
5. Одну строку: открыть чистый чат через `/new`, если команда доступна, либо через New Chat и вставить промпт. Не утверждай, что выдача промпта сама открыла новый чат.

## Типовые ошибки

| Ошибка | Обязательная коррекция |
|---|---|
| Старый PASS считается текущим | Укажи проверенный commit/state, более поздние правки пометь непроверенными. |
| Dirty-файлы скрыты | Раздели staged, unstaged и untracked. |
| Неясная фоновая операция запускается повторно | Зафиксируй идентификатор/статус; первым шагом сделай безопасную проверку. |
| Накопительные токены считаются заполнением окна | Используй context stats хоста; cumulative usage не равно occupancy. |
| Новый промпт говорит только «продолжи» | Назови одно исполнимое действие и evidence для его завершения. |
